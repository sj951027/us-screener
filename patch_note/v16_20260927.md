## 왜 (실측·리뷰)

- 1: 배당 1,304건은 queued_at 이 전부 `2026-09-04T23:51:26` 로 같다. v15 는 같은 ORDER BY 로 두 번 조회해 두 번째를 `OFFSET` 으로 이었는데,
  동률 행의 순서는 보장되지 않아 같은 심볼이 한 실행에 두 번 뽑히거나 일부가 계속 건너뛰어질 수 있었다.
- 2: v15 는 `reason != 'div'` 전체(분할 포함)를 `cap − 예약` 으로 잘라, 분할이 150건을 넘는 날엔 초과분이 배당 뒤로 밀렸다(분할 = 50% 가짜 절벽).
- 3: 러너 #68(일요일 수동 실행)이 `valuation_rotate` 에 **20260926(토) 542행**을 넣어 전날 정기 실행분과 합쳐 비거래일 라벨 1,066행이 됐다(정본 실측).
  `et_today()` 는 달력 날짜라 주말·휴장일 실행에서 비거래일을 낸다. CLAUDE.md: "run_id는 미국 거래일(ET) 앵커".
- 4: v15 는 적재만 막고 계산·CSV 저장은 그대로 해서, 최신일이 이틀 연속 같은 날(9/23 유형) 페이지 CSV 는 두 번째 계산, score_daily·us_tilt.csv 는
  첫 번째 계산이 되어 같은 날짜의 순위가 화면과 기록에서 달랐다. 계산 자체를 건너뛰면 불일치도, 매 실행 3천여 종목 재계산도 없다.
- 5: v15 의 '전부 실패면 위치 유지'는 실패가 며칠 이어지면 순환 전체(나머지 약 6천 종목의 시총·섹터)를 멈춘다.
- 7: 러너 #68 `응답 {403: 17}` · 로컬 직접 조회에서 `shrt20260831.csv` 200 / `shrt20260915.csv` 403 AccessDenied(같은 IP·UA) → 차단이 아니라 파일 없음.
