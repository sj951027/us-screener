# v12 — 날짜 지정 누락 시세 복구와 과거 결손 검사

## 무엇을
- Actions 수동 입력 `price_repair_dates` 추가. 예: `20260922`.
- `us_price_repair.py`: 지정일 앞뒤 관측일에 모두 존재하는 종목 중 지정일에 없는 종목만 명시적 start/end로 요청. 지정일 행만 INSERT OR IGNORE. 기존 행 덮어쓰기 없음.
- 잔여 누락 또는 요청 예외는 실패 종료. 점수 생성과 Release 업로드로 진행하지 않는다. 부분 복구는 러너에만 남고 기존 정본은 유지한다.
- 일상 실행에도 최근 관측일 20개의 부족한 날짜를 Actions warning으로 표시한다.
- 페이지 적재 게이트·알림의 분모를 직전 하루에서 이전 최대 20개 관측일의 최대 행수로 변경. 점수식 불변.

## 실행 절차
사용자가 커밋·푸시 후 Actions → collect-us-data → Run workflow:
- `price_repair_dates`: `20260922`
- `repair_dates`: 빈 값(빈 점수 날짜는 기존 최근 10거래일 자동 보충이 담당).
- 로그 `[시세 복구] ... 잔여 0`과 자동 보충, 정본 업로드 성공을 확인한다. 이후 최신 정본의 날짜별 행수와 score_daily를 다시 조회해야 복구 완료로 판정한다.
- 점수가 일부 존재하거나 자동 보충 창 밖이면 시세 복구 후 별도 `repair_dates`를 지정한다. 이는 해당일 점수를 삭제 후 다시 계산하므로 필요 날짜만 지정한다.

## 남은 한계
- 거래소 캘린더를 사용하지 않는다. 0행 거래일은 audit 목록에 없고, 휴장일 잔행은 점검 경고가 날 수 있다. 자동 복구일 추정은 하지 않는다.
- 앞뒤 공통 종목 방식은 신규 상장·상폐 종목의 해당일 누락을 모두 복원하지 못한다. 잔여 0은 이 기준 집합 안에서의 완료다.
- 기존 잘못된 가격·NULL 행·분할 조정 오류는 이 복구 범위 밖이다. 기존 행 유지가 우선이다.
- 야후에 요청한 날짜가 실제로 제공되지 않으면 실패로 남는다. API 성공을 데이터 복구 성공으로 간주하지 않는다.
- 20일 최대값은 거래소 달력·상장목록 기반 기대 종목 수의 대체 근사다. 대규모 상장 감소 시 경고가 날 수 있다.
