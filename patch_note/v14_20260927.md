# v14 (2026-09-27) — 전수 점검 후속: 복구 기준일 정정 · 실패선을 게이트에 맞춤 · 정본 덮어쓰기 3차 방어 · '0행=완료' 박제 제거 (점수식 무변경)

2026-09-27 전수 점검(정본 tar 실측 + 코드 통독)에서 나온 결함 중 **데이터를 잃거나 조용히 망가뜨리는 것** 4묶음만 고쳤다.
나머지(재조정 큐 배당 굶김·NDX100 멤버십·시총 스냅샷 날짜·지수 시계열 14일 창 등)는 다음 패치로 남긴다.

## 무엇을

### 1. us_price_repair.py — 복구 기준일이 휴장일 잔행·부분 수집일을 건너뛰게
- `anchors(con, day, counts)` 신설: 복구일 앞뒤에서 **행수 ≥ 직전 20관측일 최대 × MIN_COVERAGE(90%)** 인 날만 기준일로 쓴다.
  `missing()` 은 이 기준일 두 날의 공통 종목을 기준 집합으로 삼는다(이전엔 단순히 '바로 앞/뒤 날짜').
- `date_counts()` 로 날짜별 행수 집계를 한 번만 하고 `anchors`·`missing`·`gaps`·`repair` 가 재사용한다(491만행 전수 집계라 호출마다 하면 느리다 — 로컬 실측 회당 ~25초).

### 2. us_price_repair.py — 실패선을 점수 게이트와 같은 자리로
- `bulk_gap()` = **커버리지 `(기준−잔여)/기준 < MIN_COVERAGE(90%)`** — page_data 게이트와 같은 식. 복구가 '성공'이라 한 날은
  게이트도 통과하고, '실패'라 한 날은 게이트도 막는다. (`1 - .9` 같은 부동소수 임계를 쓰면 정확히 10% 인 날에 두 판정이 갈린다 —
  리뷰에서 발견해 같은 식으로 통일.)
- `RESIDUAL_WARN_FRAC = .01`: 잔여 1% 초과~게이트 통과 구간은 `::warning::` 한 줄(게이트는 통과하지만 결손이 큼).
- `repair_dates(con, dates, …)` 로 main 의 판정 루프를 분리(테스트 가능) — 행수 집계는 실행당 1회만 하고 날짜 간에 공유한다
  (앞 날짜의 복구분이 뒤 날짜의 기준일 판정에 반영). 앞뒤에 온전한 날이 없을 때의 오류 문구에 '최신 세션은 다음 정기 실행이 채운다'를 넣었다.

### 3. .github/workflows/collect-data.yml — 자산 소실을 '새로 시작'으로 오인하지 않게
- 릴리스에 `us-data.tar.gz` 는 없고 `us-data-weekly.tar.gz` 는 있으면 **중단**(exit 1) + 복구 절차 출력.
  둘 다 없을 때만 새로 시작.

### 4. 수집기 4종 — '0행 = 완료' 박제 제거
- `us_insider_collector.py`: 파싱 0행이면 기존 분기 삭제·완료 표기 없이 건너뜀(다음 실행 재시도).
- `us_xbrl_collector.py` · `us_earnings_collector.py`: 파싱 0개면 `last_success` 를 올리지 않고 **`last_attempt`(시도일)만** 기록,
  ✅ 성공 문구 대신 ❌ 한 줄. 주간 가드는 성공일·시도일 중 늦은 쪽을 본다 — 실패를 성공으로 박제하지 않으면서도 매일 1.3GB
  재다운로드로 번지지 않게(주 1회 재시도). 리뷰에서 '가드가 풀리면 매일 2.6GB' 지적을 받아 이렇게 정했다.
- `us_short_collector.py`: 파싱 0행이면 `short_files_done` 에 기록하지 않음(1초 대기 후 다음 후보) + 상태코드 집계
  (`응답 {200: n, 404: m, ...}`) 출력, 후보 전부 403/5xx/예외면 ❌ 차단 의심 한 줄(us_shortvol 과 같은 방식).
