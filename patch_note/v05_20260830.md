# v05 (2026-08-30) — 옵션 요약 스냅샷 수집기 신설 (us_options_collector)

## 무엇을
1. `us_options_collector.py` 신설 (데이터 확장 4차) → `us_options.db` `option_daily`:
   유동성 상위 500(가드 close≥$5) ∪ 관측 모델 종목(us_mus_v0 top50·us_rvdtc_a 풀)의
   근월 1~2개 만기(5≤DTE≤75)에 대해 call/put OI·거래량, ATM IV(콜·풋),
   스큐(0.9S 풋 IV − ATM 풋 IV)만 저장. 하루 ~1,000행(연 ~10MB 수준).
2. 워크플로 `collect-data.yml`: Build page data 스텝 뒤에 Options snapshot 스텝 추가
   (오늘 score_daily 반영 뒤 실행되도록). tar·무결성 게이트는 *.db 글롭이라 자동 포함.

## 왜 (사용자 결정 2026-08-30)
옵션 지표는 '큰돈의 방향 베팅' 전조 후보인데 **과거 이력을 무료로 소급할 수 없다** —
지금부터 쌓아야 1년 뒤에나 시험 가능. "데이터원에서 받아놓고 쌓는 것과 검증은
별개"라는 사용자 지적이 타당해 선제 수집 개시. 관측 전용, 점수 미투입.

## 커밋 전 리뷰 반영 (2026-08-30)
- **"부분 종료 후 다음 날 이어받음" 서술이 틀렸음(사용자 지적)**: 스냅샷은 날짜별
  데이터라 잘린 꼬리는 그 날짜분이 영구 결손이고, 매일 같은 순서면 만성 결손이 됨.
  수정: ① 예산 25→35분(러너 실측: 정상일 수집부 40~60분, 타임아웃 180분 — 커밋
  타임스탬프로 확인) ② snapshot_log 테이블 신설(일별 계획/성공/실패/소요/잘림)
  ③ 다음 실행이 직전 실측 속도로 계획을 예산 안에 자동 축소 — "매일 완주"로 수렴
  (시뮬레이션: 어제 350심볼/2100s 잘림 → 오늘 315심볼 계획, 예상 1890s < 2100s 확인)
  ④ 잘림 로그를 "영구 결손"으로 정직하게 표기. self-test 12항목으로 확장.
- 유니버스 순서 결함 수정: 시간예산 부분 종료 시 목록 끝의 관측 모델 종목이 잘릴 수
  있었음 → 모델 종목을 맨 앞으로(검증: 순서 assert 추가 확인). 잘리는 꼬리는 유동성
  최하위가 되도록 유지.
- 엣지 6종 추가 확인: 관계컬럼 전무 zip(경고+플래그0 보존), 소문자 relationship,
